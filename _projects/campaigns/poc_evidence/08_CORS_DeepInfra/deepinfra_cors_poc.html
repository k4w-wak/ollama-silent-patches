api.deepinfra.com | Origin Reflection + Credentials = Critical
CRITICAL — CVSS 9.1

Vulnerability Details

Target: api.deepinfra.com
Type: CORS Misconfiguration — Origin Reflection with Credentials
Severity: Critical (CVSS 9.1)
Impact: Full account takeover, API key theft, data exfiltration, account deletion
Root Cause: The API server reflects ANY Origin header back in Access-Control-Allow-Origin while also setting Access-Control-Allow-Credentials: true. This allows any malicious website to make authenticated cross-origin requests that carry the victim's session cookies.

Affected Endpoints:
• GET /v1/me — User profile data (email, name, org, balance)
• GET /v1/api-tokens — Lists ALL API tokens (the keys themselves!)
• DELETE /v1/me — Permanently deletes the victim's account
• DELETE /v1/api-tokens/{id} — Deletes specific API tokens
• PATCH /v1/me — Modify user profile (email, password, etc.)

Bypass Tested: Null origin, arbitrary subdomains, attacker-controlled origins — ALL reflected.

How This Attack Works

Step 1 — Lure: Attacker sends victim a link to this HTML page (or embeds it in any website).

Step 2 — Auto-Auth: When the victim visits, their browser automatically includes their deepinfra.com session cookies in every fetch() request because Access-Control-Allow-Credentials: true is set.

Step 3 — Read: Because the server reflects ANY origin in Access-Control-Allow-Origin, the browser allows the malicious JavaScript to READ the response — this is the key difference from a same-origin policy violation.

Step 4 — Exfiltrate: The attacker's JavaScript reads:
  • User profile (email, name, org, balance) from /v1/me
  • ALL API tokens from /v1/api-tokens

Step 5 — Destroy: The attacker can DELETE /v1/me to permanently delete the victim's account — no CSRF token needed since CORS allows it.

Remediation

1. Whitelist Specific Origins: Never reflect arbitrary Origin headers. Maintain an explicit allowlist:
Access-Control-Allow-Origin: https://deepinfra.com

2. Remove Credentials for Wildcard: If using *, you MUST NOT set Access-Control-Allow-Credentials: true — browsers block this combo, but origin reflection is worse because it bypasses this protection.

3. Restrict Methods: Only allow necessary methods. DELETE and PATCH on user accounts should never be CORS-accessible from arbitrary origins.

4. CSRF Tokens: Add CSRF token validation for state-changing operations (DELETE, PATCH, POST).

5. Scope API Tokens: The /v1/api-tokens endpoint should require an Authorization header (bearer token), not just session cookies.
